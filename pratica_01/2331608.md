## 1. Introdução

Nesta prática, foi testado o método `processarClusters` da classe `BioClusterManager` usando três abordagens: teste baseado em especificação, teste estrutural (MC/DC) e teste baseado em mutação.

A ideia foi cobrir cenários normais, casos de borda e tentar melhorar a qualidade do conjunto de testes.

---

## 2. Método testado (resumo)

```java
public List<String> processarClusters(List<Observation> obs, double raio, double threshold,
        boolean modoInter, int limiteSeguranca)
```

Comportamento observado:

1. Retorna lista vazia quando `obs.size() < 2`.
2. Para cada par `(o1, o2)`, calcula distância.
3. Cria conexão quando a condição composta é verdadeira.
4. Interrompe quando atinge `limiteSeguranca`.

Condição principal:

```text
(dist < raio && (mesmaEspecie || modoInter))
&& (o1.saude > threshold || o1.saude > threshold)
&& !(o1.invasora && o2.invasora)
```

---

## 3. Teste baseado em especificação

### 3.1 Partições de equivalência

- Quantidade de observações: `< 2` e `>= 2`
- Distância: `< raio` e `>= raio`
- Espécie/interação: mesma espécie, espécies diferentes com `modoInter = true`, espécies diferentes com `modoInter = false`
- Saúde: `> threshold` e `<= threshold`
- Invasoras: ambas invasoras / não ambas invasoras
- Limite de segurança: sem corte / com corte antecipado

### 3.2 Casos de teste

| ID | Objetivo | Resultado esperado |
| --- | --- | --- |
| CE01 | Lista com 1 observação | Retorna vazio |
| CE02 | Cenário válido básico | Cria 1 conexão |
| CE03 | `dist == raio` (borda) | Não cria conexão |
| CE04 | Espécies diferentes sem modo inter | Não cria conexão |
| CE05 | Espécies diferentes com modo inter | Cria conexão |
| CE06 | Duas invasoras | Não cria conexão |
| CE07 | `saude == threshold` | Não cria conexão |
| CE08 | `limiteSeguranca = 1` com vários pares válidos | Para na 1ª conexão |

Observação: nos testes, percebe-se que só `o1.saude` afeta a condição, por causa da repetição no código.

## 4. Teste estrutural (MC/DC)

### 4.1 Predicados da decisão

- `A`: `dist < raio`
- `B`: `o1.getEspecieId() == o2.getEspecieId()`
- `C`: `modoInter`
- `D`: `o1.getSaude() > threshold`
- `E`: `o1.getSaude() > threshold` (duplicado)
- `F`: `o1.isInvasora() && o2.isInvasora()`

Decisão analisada:

```text
R = (A && (B || C) && (D || E) && !F)
```

### 4.2 Tabela reduzida para derivação dos testes

| Caso | A | B | C | D | E | F | R |
| --- | --- | --- | --- | --- | --- | --- | --- |
| M1 | T | T | F | T | T | F | T |
| M2 | F | T | F | T | T | F | F |
| M3 | T | F | F | T | T | F | F |
| M4 | T | F | T | T | T | F | T |
| M5 | T | T | F | F | F | F | F |
| M6 | T | T | F | T | T | T | F |

Pares usados:

- `A`: M1 × M2
- `B`: M1 × M3
- `C`: M3 × M4
- `D/E`: M1 × M5
- `F`: M1 × M6

### 4.3 Cobertura (JaCoCo)

Resumo da cobertura observado (comparando suíte reduzida x suíte completa):

| Momento | Line coverage | Branch coverage |
| --- | --- | --- |
| Antes dos testes MC/DC (baseline) | 92% | 63% |
| Depois dos testes MC/DC (suíte completa) | 100% | 90% |

Interpretação curta: o ganho principal apareceu em cobertura de decisão/ramificação, que era o foco do critério MC/DC.

### 4.4 Defeitos, erros e falhas encontrados

1. Repetição da condição de saúde:
   - Atual: `(o1.getSaude() > threshold || o1.getSaude() > threshold)`
   - Provável intenção: segunda parte usar `o2.getSaude()`.
2. Essa duplicação reduz a qualidade da decisão e impacta o próprio MC/DC.

## 5. Teste baseado em mutação (PIT)

Passos usados:

1. Rodar PIT com conjunto inicial.
2. Analisar mutantes sobreviventes.
3. Adicionar casos de borda.
4. Repetir.

### 5.1 Evolução do score

| Rodada | Score de mutação | Observação |
| --- | --- | --- |
| Execução no ambiente montado | 84% | 25 mutações geradas, 21 mortas, sem mutações sem cobertura |
| Leitura geral | - | Resultado bom para a prática, mas ainda com espaço para melhorar em mutantes matemáticos |

### 5.2 Resumo textual dos mutators

- ConditionalsBoundaryMutator: 7/7 mortos (100%)
- NegateConditionalsMutator: 11/11 mortos (100%)
- EmptyObjectReturnValsMutator: 2/3 mortos (67%)
- MathMutator: 1/4 mortos (25%)

Leitura rápida: os mutantes ligados à lógica condicional foram bem cobertos; os sobreviventes ficaram mais concentrados em mutação matemática/retorno.

## 6. Conjunto de testes implementados

```java
import static org.junit.jupiter.api.Assertions.*;
import java.util.*;
import org.junit.jupiter.api.Test;

public class BioClusterManagerTest {

    private Observation o(int id, int esp, double x, double y, double saude, boolean inv) {
        return new Observation(id, esp, x, y, saude, inv);
    }

    @Test
    void ce01_listaComUmElemento() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(o(1, 1, 0, 0, 0.9, false));
        assertTrue(m.processarClusters(obs, 10, 0.5, false, 10).isEmpty());
    }

    @Test
    void ce02_cenarioValido() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.9, false),
            o(2, 1, 1, 1, 0.2, false)
        );
        assertEquals(1, m.processarClusters(obs, 5, 0.5, false, 10).size());
    }

    @Test
    void ce03_distanciaIgualRaio() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.9, false),
            o(2, 1, 3, 4, 0.9, false)
        );
        assertTrue(m.processarClusters(obs, 5, 0.5, false, 10).isEmpty());
    }

    @Test
    void ce04_especiesDiferentesSemInter() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.9, false),
            o(2, 2, 1, 1, 0.9, false)
        );
        assertTrue(m.processarClusters(obs, 5, 0.5, false, 10).isEmpty());
    }

    @Test
    void ce05_especiesDiferentesComInter() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.9, false),
            o(2, 2, 1, 1, 0.9, false)
        );
        assertEquals(1, m.processarClusters(obs, 5, 0.5, true, 10).size());
    }

    @Test
    void ce06_duasInvasoras() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.9, true),
            o(2, 1, 1, 1, 0.9, true)
        );
        assertTrue(m.processarClusters(obs, 5, 0.5, false, 10).isEmpty());
    }

    @Test
    void ce07_saudeNoLimite() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.5, false),
            o(2, 1, 1, 1, 0.9, false)
        );
        assertTrue(m.processarClusters(obs, 5, 0.5, false, 10).isEmpty());
    }

    @Test
    void ce08_limiteSeguranca() {
        BioClusterManager m = new BioClusterManager();
        List<Observation> obs = List.of(
            o(1, 1, 0, 0, 0.9, false),
            o(2, 1, 1, 1, 0.9, false),
            o(3, 1, 2, 2, 0.9, false)
        );
        assertEquals(1, m.processarClusters(obs, 10, 0.5, false, 1).size());
    }
}
```

## 7. Conclusão

A prática foi útil para comparar três técnicas diferentes no mesmo método. O teste por especificação ajudou a organizar entradas, o MC/DC ajudou na análise lógica e a mutação mostrou onde os testes ainda estavam fracos.

Também foi possível identificar um defeito real no código (repetição da condição de saúde), que afeta o comportamento e a testabilidade.
